# Firmverse virtual-device trace ABI

`FVD1` is a 64-byte little-endian block exported by Cortex-M firmware and read
from guest RAM after the completion breakpoint. It is deliberately data-only:
CI does not depend on debug strings or timing-sensitive UART output.

| Word | Field | Meaning |
| ---: | --- | --- |
| 0 | magic | `0x31445646` (`FVD1`) |
| 1 | version | ABI version, currently `1` |
| 2 | byte length | Must be `64` |
| 3 | status | `0` running, `1` pass, `2` fail |
| 4 | capabilities | buttons `1`, display `2`, TRNG `4`, atomic storage `8`, secure-element boundary `16` |
| 5 | button events | Consumed physical-input events |
| 6–7 | display | Presented frame count and deterministic digest |
| 8–9 | TRNG | Generated byte count and digest |
| 10–12 | storage | Successful commits, selected generation and record digest |
| 13–14 | secure element | Boundary operation count and response digest |
| 15 | failure code | Firmware-defined non-zero diagnostic |

A workflow requests the trace with `device-trace-symbol` and can fail closed on
missing behavior through `required-device-capabilities`. The ABI describes
observable device behavior; it does not claim electrical, timing or
side-channel fidelity. Those remain hardware-in-the-loop responsibilities.

For the default `mps2-an505` backend, Firmverse links Secure code at `0x10000000` and uses Secure SRAM at `0x38000000`, matching the board model's TrustZone aliases. The FVD1 block is writable RAM and must be published by executing firmware before `firmverse_done`.
